# 回归测试

在项目根目录运行 `uv run pytest -q`。默认测试使用模拟模型，不调用收费 API。

覆盖分阶段模块加载、HTTP 会话与实时事件、停止/重连/导出、工具循环、三种观察模式、长文件原子编辑和本机命令执行。Shell 测试会在临时目录运行短命令，并检查超时和取消清理。

`support/cua_verifier.py` 仅供可选桌面验收脚本独立读取目标状态；不作为产品模式，也不放进学生发布包。旧的 `test_reference.py` 验证第二课所带的 Agent 标准实现。

第一课教学骨架由 `test_lesson_one_scaffold.py` 验证：只补五个辅助函数仍不能接管对话，必须完成自己的 run_turn；检查器拒绝提前返回、漏写工具结果和超出轮数等循环错误。未完成步骤立即提示，停止信号继续向外传递。面向学生的逐步检查位于 `lesson_01_agent/check.py`，使用假模型和假工具。

`test_learning_edit.py` 验证先接入 Edit 的流程：初始 TODO 不开放工具；学生完成声明与分发后，实际调用保存的分发函数。临时课程中通过 HTTP 聊天调用真实编辑器，完成辅助函数和 Loop，再由新保存的学生循环接管并自检。模型回复固定，文件读写与源码加载真实执行；另检查版本冲突、批量拒绝、路径限制、语法拒绝和原始字节备份。接入检查器位于 `lesson_01_agent/check_edit.py`。

`test_learning_chat.py` 验证预置教学 Chat 的列目录/读文件、文件访问边界、检查缓存/语法错误/超时，以及保存完整源码后真正执行学生 `run_turn()` 并自检，再改坏时回到教学 Chat；使用临时课程副本和假模型，不修改作业文件。

`test_clear_conversation.py` 验证批量清理历史会话：保留当前对话上下文及运行中任务、历史只读会话的保留、清理后重启不恢复、CSRF 和无效请求校验、文件移动失败时整批回滚。

`test_fixed_experiments.py` 验证固定实验会话：按课时预置、清理保护、提示词预填、重置消息与模型上下文、运行记录归档、重启恢复、重新执行、模型设置限制及 CSRF / 运行中保护。

`test_session_persistence.py` 验证普通会话多轮后重启仍只有一个入口、工具请求/结果与模型元数据恢复、再次重启继续归组、同名独立会话不合并、按会话清理全部轮次，以及中断上下文隔离、旧版只读记录保留、截图与密钥处理、保存失败时原记录不受损。
