# 从 LLM API 到本机 Agent

## 第一课 · Agent 与工具循环

### A.1 实现

先启动单步教学 Chat，每次工具返回后点击“继续下一步”或发送补充消息，由你手动推进。随后与它一起完成 `lesson_01_agent/tools.py` 的工具声明与执行分发，接入 Edit。初次接入手动粘贴保存，通过后下一轮 Chat 获得编辑能力；再用它阅读、讨论、实际修改 agent.py 并检查，直到 Loop 完成后由自己的 Agent 接手。

按 [第一课 README](../../lesson_01_agent/README.md) 完成 `lesson_01_agent/agent.py` 的四个小函数：保存回复、解析参数、执行工具、包装结果。将四个函数作为一个阶段一起完成，再与 Chat 实现核心 `run_turn()`：请求模型、遍历工具、回传结果、继续循环。消息准备和 `lesson_io` 已提供，网页事件、错误转换、停止传播与图片无需自己写。Edit 保存后直接附带检查结果，不需要每个函数单独编辑、单独检查。

LLM 客户端已提供。「测试 LLM」只验证接口连接，不经过学生函数；辅助函数和自己写的循环均需通过离线检查和普通发送验证。完成后，让模型调用 calculate 和 get_current_time，并根据工具结果继续调用。

解释：模型在哪一步返回决定？工具在哪一步实际执行？如果不把结果交回模型会怎样？

### A.2 长文件局部编辑：比较模型的代码修改能力

选择两个不同代际的模型，记录完整模型 ID、日期、配置和供应商。默认使用 GPT‑6.1 Sol；列表中也保留两代 Gemini Flash，允许自选有依据的比较组合。

从左侧「固定实验」打开唯一的「长文件局部编辑」，输入框已填好原始提示词。课初已完成作业文件的 Edit 接入；这个实验提供 `search_file`、`read_file` 和 `edit`，用于独立长文件副本的模型比较。完成通用 Agent 循环后即可使用，无需为这道题单独写一个特殊 Agent。

原始 `course_page.py` 是 5,000 行合成课程页面代码，含 CourseA、CourseB、CourseC。三门课均有同名 `format_title` 方法和两处调用。只将 CourseB 的定义改为 `format_course_title`，同步该课程的 `render_card`、`render_outline` 调用；A、C 以及注释、正文、空白必须保持原样。课程 B 的目标位置是 1808、2060、3100 行；工具编辑依据文本上下文，不依据固定行号。

模型先用 `search_file` 搜索和分段 `read_file` 确认作用域，再输出含三处替换的 `edit` 调用。程序负责检查当前版本、唯一匹配和补丁不重叠，全部通过才原子写入，最后把 diff 交回模型。错误也要交回模型，让它修正上下文或重新读取，不能在 Agent 中猜测并擅自修补模型的参数。

两个模型各运行两次，每轮先导出记录，再点击「重置实验」清空上下文，下次发送时从相同基线重建副本。验收共 8 项：语法；B 的定义；B 的两处调用；A 不变；C 不变；其他所有字节不变；课程方法行为。只有精确符合预期三处修改的已知程序才执行行为检查，不执行任意模型代码。

提交原始文件、最终文件、diff、验收结果、费用、耗时和工具调用次数。分别比较定位是否正确、是否漏改、是否误伤同名函数、补丁能否应用、失败后能否恢复。把“API/工具循环跑通”和“代码改对”分成两列，不因单个样例得出普遍模型排名。

图中的“流式”可作为拓展题：在 Web 工作台 展示生成进度，但完整收到并校验工具参数后才应用补丁。当前框架按工具步骤实时展示简化 trace，提交结果原位更新，完整 diff 可在导出记录中查看；不要求学生实现 token 级流式解析。

## 第二课 · Computer Use

### B.1 实现

第一课的 Agent 标准实现已提供。完成 `lesson_02_computer_use/cua.py`，让自己的 Agent 操作本机应用。至少演示一次“观察 → 操作 → 再观察 → 回答”。普通聊天与电脑任务仍使用同一个 Agent 循环。

### B.2 观察方式

普通对话中可选择以下观察方式；第二课不另设固定实验。

| 模式 | 提供的信息 | 可用定位方式 |
| --- | --- | --- |
| 纯视觉 | 窗口截图及必要坐标/窗口元数据 | 像素坐标与键盘 |
| Accessibility Tree | 控件角色、标签、值、层级及窗口元数据 | 元素 token、树中坐标与键盘 |
| 混合 | 截图和树 | 两种定位方式 |

演示时选择一个已打开的本机应用，独立核对操作后的状态。应用中的树可能为空或不完整，应如实记录。停止或重置会话不会撤销已经执行的电脑操作。

## 提交

1. 三个学生模块（第一课 tools.py 与 agent.py、第二课 cua.py）。
2. 一段浏览器 Agent 与本机应用同时可见的演示录屏。
3. 导出的运行记录，和独立核对应用最终状态的证据。
4. 一张对比表：模型、任务、观察模式、是否完成、时间、工具次数、人工帮助次数、费用（若可得）。
5. 分析两次失败：第一处错误在哪、是否恢复、你的干预如何改变结果。

第一轮不人工帮助；第二轮可以自由指挥，但分开记录。保留所有失败，不把小样本结果写成普遍模型排名。

建议评分：实现 40%，实验规范 20%，行为分析 30%，表达 10%。不按模型本身的成功率给学生打分。
